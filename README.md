<h1 align="center">Reboil</h1>

<p align="center">
  Small, fast, and scalable string-path state access for web applications and React Native, with code splitting, and synchronous persistence out of the box
</p>

<p align="center">
  The core store API is framework agnostic. React bindings are available as an optional integration.
</p>

## Why Reboil?

- Typed dot-path access such as `settings.theme` and `todos.0.title`
- Path-level React subscriptions with precise rerenders
- Synchronous hydration and writes through `localStorage` on the web and MMKV on native
- Immutable updates with direct values or updater functions
- Typed persistence exclusions and synchronous schema migrations
- Vanilla JavaScript subscriptions and development-time mutation logging
- A framework-agnostic core API with optional React bindings
- A single application store with a small API

## Platform support

| Platform                               | Persistence    | Notes                                                           |
| -------------------------------------- | -------------- | --------------------------------------------------------------- |
| Web browsers and Expo Web              | `localStorage` | Works with vanilla JavaScript and browser frameworks            |
| Expo / React Native on iOS and Android | MMKV           | Requires a development or production build                      |
| Server environments                    | In memory      | Persisted hydration and server-side mutations are not supported |

Expo Go is not supported because MMKV contains native code.

## Installation

For web applications, including vanilla JavaScript and browser frameworks:

```sh
npm install @reboil/store
```

For Expo and React Native, install Reboil and its native peer dependencies, then create a native build:

```sh
npx expo install @reboil/store react-native-mmkv react-native-nitro-modules
npx expo prebuild
```

Then register the application state and wire the generated config into the entry point:

```sh
npx @reboil/store init
```

## Quick start

Run the initializer command at your project directory after installing the package.

```sh
npx @reboil/store init
```

It creates the application state and config files, registers their types, and wires the config into the application entry point.

To add the maintained project-local skills for Claude Code and Codex, run:

```sh
npx @reboil/store --prepare agents
```

```ts
// src/state.ts - created by the init command
export const initialState = {
  count: 0,
  settings: {
    runtimeVersion: '3.14.15',
    theme: 'light' as 'light' | 'dark',
  },
}
```

```ts
// reboil.config.ts - generated by the init command
import { createStore, defineConfig } from '@reboil/store'
import { initialState } from './src/state'

createStore(initialState)

export default defineConfig({
  stateFile: './src/state.ts',
})

declare module '@reboil/store' {
  interface Register {
    state: typeof initialState
  }
}
```

Next.js App Router projects use the framework entry point generated by the initializer:

```tsx
import { ReboilState } from '@reboil/store/next'
import reboilConfig from '../../reboil.config'

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return <ReboilState config={reboilConfig}>{children}</ReboilState>
}
```

For Next.js, `ReboilState` provides the client boundary and accepts the same config object returned by `defineConfig` in every other project type. The root layout stays a Server Component, and no `register-state.ts` bridge is required. The config is a static import rather than a path string so Next.js can include custom and lazy state modules in the client bundle.

## Usage

Subscribe to only the path a component needs, then update it through the same store:

```tsx
// src/Counter.tsx
import { store } from '@reboil/store'
import { useStore } from '@reboil/store/react'

export function Counter() {
  const count = useStore('count')

  return (
    <button type="button" onClick={() => store.set('count', (value) => value + 1)}>
      Count: {count}
    </button>
  )
}
```

Paths and values remain type-safe:

```ts
store.get('settings.theme') // 'light' | 'dark'
store.set('settings.theme', 'dark') // valid
store.set('settings.runtimeVersion', 3.14) // TypeScript error
store.set('settings.theme', 'blue') // TypeScript error
store.subscribe('count', (value, previous) => previous) // valid
```

State persists by default. Reboil accepts JSON-safe plain objects, arrays, strings, finite numbers, booleans, and `null`.

## Code-split stores

A `createStore()` result can be nested directly in another store. Wrap a dynamic import with Reboil's `lazy()` when a feature should be emitted as a separate bundle and loaded only when it is used:

```ts
// src/features/reports/state.ts
import { createStore } from '@reboil/store'

export default createStore({
  count: 1,
  filters: { query: '' },
})
```

```ts
// reboil.config.ts
import { createStore, lazy } from '@reboil/store'
import { initialState } from './src/state'

export const reports = lazy(() => import('./features/reports/state'))

export const app = createStore({
  ...initialState,
  reports,
})

// ... rest of reboil.config.ts
```

React access starts the import and suspends while the feature store loads, so place a Suspense boundary around the feature:

```tsx
import { Suspense } from 'react'
import { useStore } from '@reboil/store/react'

function Reports() {
  const count = useStore('reports.count')
  return <p>{count} reports</p>
}

export function ReportsRoute() {
  return (
    <Suspense fallback={<p>Loading reports…</p>}>
      <Reports />
    </Suspense>
  )
}
```

Vanilla code remains synchronous after explicitly loading the partition. The root and scoped bindings refer to the same state:

```ts
import { store } from '@reboil/store'

await store.load('reports')
store.set('reports.count', 2)
reports.store.get('count') // 2
```

Use `lazy` from `@reboil/store`, not React's component-oriented `lazy`. A lazy store loads once and stays resident for the application session.

## Persistence

State persists by default. Exclude values that should return to their initial value whenever the page or app reloads:

```ts
const state = {
  count: 1,
  settings: {
    runtimeVersion: '3.14.15',
  },
}

createStore(state, {
  persist: {
    exclude: ['count'],
  },
})
```

Here, `count` is never persisted, so it always resets to `1` after a reload. Other state, such as `settings.runtimeVersion`, continues to persist normally.

Mutations are validated and persisted before the in-memory state is committed. Failed validation, serialization, or storage writes leave the previous state authoritative and throw an error.

## Migration

Use a migration when a new release makes a breaking change to the shape of persisted state, such as renaming a field or changing its type. Increment the store version and synchronously convert the older state to the current shape:

```ts
const state = {
  count: 1,
  settings: {
    runtimeVersion: '3.14.15',
  },
}

createStore(state, {
  version: 2,
  migrate(persisted, fromVersion) {
    if (fromVersion !== 1) {
      throw new Error(`Unsupported schema version: ${fromVersion}`)
    }

    const previous = persisted as {
      count?: number
      settings?: { runtime?: string }
    }

    return {
      count: previous.count ?? 1,
      settings: {
        runtimeVersion: previous.settings?.runtime ?? '3.14.15',
      },
    }
  },
})
```

This example migrates the version-one `settings.runtime` field to `settings.runtimeVersion`. Additive changes usually do not need a migration because persisted objects are merged with the current defaults. A failed or unsupported migration preserves the previously stored data and throws an error.

## API

| API                                   | Purpose                                                   |
| ------------------------------------- | --------------------------------------------------------- |
| `createStore(initialState, options?)` | Register the application store and return typed bindings  |
| `lazy(loader)`                        | Define a code-split store from a dynamic import           |
| `store.get(path)`                     | Read the current value at a path                          |
| `store.set(path, valueOrUpdater)`     | Validate, persist, and commit a value                     |
| `store.subscribe(path, listener)`     | Subscribe outside React; returns an unsubscribe function  |
| `store.reset(path?)`                  | Restore a path or the complete store to its initial value |
| `store.load(path)`                    | Load a lazy partition for synchronous vanilla access      |
| `useStore(path)`                      | Subscribe a React component to one path                   |
| `setStore(path, valueOrUpdater)`      | Update the registered store through `@reboil/store/react` |

## Development

Install dependencies and verify the package from the repository root:

```sh
npm install
npm run build
npm test
npm run typecheck
```

Start an internal prototype with its workspace name:

```sh
npm run dev --workspace reboil-parcel-app
```

The documentation site has its own dependency tree and requires Node.js 20 or newer:

```sh
npm install --prefix docs-site
npm run start --prefix docs-site
```
